Commands used to produce every file in this directory. All paths are
relative to the ml-graph-compiler-runtime repo root.

MLIR_BIN below is the exact path used on the development host these
artifacts were generated on -- a plain environment-variable override (see
mlir_passes/tools/compile_hir_matmul_bias_relu_aarch64.sh), not a
hardcoded requirement.

1. Rebuild AArch64 objects for all six shapes, generic + tiled-vectorized
   (fully-unrolled vectorized only for 8x8x8/16x16x16/32x32x32 -- see
   README.md for why it is not generated for the other three):

   MLIR_BIN=/home/allen/Desktop/Project/.deps/mlir21-root/usr/lib/llvm-21/bin

   for shape in 8x8x8 16x16x16 32x32x32 64x64x64 32x64x32 64x32x64; do
     bash mlir_passes/tools/compile_hir_matmul_bias_relu_aarch64.sh \
       --variant generic \
       mlir_passes/test/backend_codegen/matmul_bias_relu_<shape>.mlir \
       <output_dir> matmul_bias_relu_<shape>

     bash mlir_passes/tools/compile_hir_matmul_bias_relu_aarch64.sh \
       --variant tiled-vectorized \
       mlir_passes/test/backend_codegen/matmul_bias_relu_tiled_<shape>.mlir \
       <output_dir> matmul_bias_relu_tiled_<shape>
   done

   Internally, --variant tiled-vectorized runs:

     mlir-opt <input.mlir> \
       --load-dialect-plugin=build-mlir/libHIRMatMulBiasReluFusionPass.so \
       --load-pass-plugin=build-mlir/libHIRMatMulBiasReluFusionPass.so \
       --pass-pipeline='builtin.module(
         hir-matmul-bias-relu-to-linalg,
         transform-preload-library{transform-library-paths=mlir_passes/transforms/tile_vectorize_matmul_bias_relu.mlir},
         transform-interpreter{entry-point=__transform_main},
         lower-affine,
         one-shot-bufferize{bufferize-function-boundaries function-boundary-type-conversion=identity-layout-map},
         buffer-deallocation-pipeline,
         expand-strided-metadata,
         lower-affine,
         convert-vector-to-scf{full-unroll target-rank=1},
         lower-affine,
         convert-vector-to-llvm{vector-contract-lowering=outerproduct},
         convert-ub-to-llvm,convert-scf-to-cf,convert-index-to-llvm,
         convert-math-to-llvm,convert-arith-to-llvm,finalize-memref-to-llvm,
         convert-func-to-llvm,convert-cf-to-llvm,reconcile-unrealized-casts)' \
       -o <name>_llvm.mlir

     mlir-translate --mlir-to-llvmir <name>_llvm.mlir -o <name>.ll
     llc -mtriple=aarch64-linux-gnu -mcpu=cortex-a76 -filetype=asm <name>.ll -o <name>.s
     llc -mtriple=aarch64-linux-gnu -mcpu=cortex-a76 -filetype=obj <name>.ll -o <name>.o

   See mlir_passes/tools/compile_hir_matmul_bias_relu_aarch64.sh's header
   comment for a line-by-line explanation of why each pass is needed
   (particularly the three lower-affine calls and
   convert-vector-to-scf{full-unroll}, both specific to this variant).

2. Pre-bufferization tiled vector-dialect intermediate
   (tiled_vector_dialect_32x32x32.mlir only -- shows the real scf.for loops
   and bounded vector.contract/vector.transfer ops before LLVM lowering,
   i.e. the project-owned tiling+vectorization stage in isolation):

   mlir-opt <input.mlir> \
     --load-dialect-plugin=build-mlir/libHIRMatMulBiasReluFusionPass.so \
     --load-pass-plugin=build-mlir/libHIRMatMulBiasReluFusionPass.so \
     --pass-pipeline='builtin.module(hir-matmul-bias-relu-to-linalg,transform-preload-library{transform-library-paths=mlir_passes/transforms/tile_vectorize_matmul_bias_relu.mlir},transform-interpreter{entry-point=__transform_main})' \
     -o tiled_vector_dialect_32x32x32.mlir

3. Disassembly:
   full: llvm-objdump -d matmul_bias_relu_tiled_32x32x32.o   -> objdump_32x32x32.txt
   excerpts (other shapes): llvm-objdump -d <obj> | head -60 -> disasm_excerpts/tiled_<shape>_head.txt

4. Repeated-call correctness (1000 calls/shape/variant, generic +
   tiled-vectorized, all 6 shapes), mixed-shape stress (500 cycles = 3000
   calls across all 6 shapes x 2 variants with allocator noise), and the
   5-way benchmark (scalar/generic/fully-unrolled-vectorized-where-available/
   tiled-vectorized/handwritten), all on the real Raspberry Pi:

   PI_HOST=allen@100.110.37.6 \
   REPEATED_CALLS=1000 MIXED_CYCLES=500 ITERATIONS=2000 ITERATIONS_LARGE=500 \
   bash tools/run_backend_codegen_tiled_pi_integration.sh <output_dir>

   which additionally:
     - transfers all 15 .o files (6 generic, 3 fully-unrolled vectorized,
       6 tiled-vectorized), the repeated-call test, mixed-shape test, and
       5-way harness sources, plus the handwritten-kernel dependency
       sources, to the Pi via scp
     - builds all three test binaries on the Pi with g++ -O2 -std=c++17
     - runs ./repeated_call_test <shape> 1000 <variant> for all 6 shapes x
       2 variants (repeated_call_results.txt)
     - runs ./mixed_shape_test 500 (mixed_shape_results.txt)
     - runs ./tiled_benchmark 2000 200 <shape> for 8x8x8/16x16x16/32x32x32
       and ./tiled_benchmark 500 200 <shape> for the three larger shapes
       (benchmark_<shape>.json)
     - records pi_device_state.txt via:
         ssh allen@100.110.37.6 "hostname; uname -a; lscpu; gcc --version | head -1"

5. Backend metrics (backend_metrics.json) and the register-pressure
   precheck (register_pressure_32x32x32.txt) were computed by disassembling
   each .o with llvm-objdump -d --no-show-raw-insn on the x86_64 dev host
   and counting mnemonics / inspecting the K-loop body directly; see those
   files' own "methodology" notes for the exact counting rules.
